# Reusable Configuration, in Small Steps

Open [SDK Test](http://localhost:5174/sdk-test) in the running consumer app.
The Templates menu places these lessons next to **Form Connection**. Each lesson
uses local example data; nothing is sent to an email service or workflow executor.

| Order | Template                                        | One idea to learn                                               |
| ----- | ----------------------------------------------- | --------------------------------------------------------------- |
| 1     | [Form Connection](../form-connection/README.md) | A view-node binding selects a state object and its form schema. |
| 2     | Shared Configuration                            | Two steps use one complete settings object.                     |
| 3     | Reusable Property                               | Share one field while other settings remain independent.        |

## 1. Share a Whole Configuration

Choose **Shared Configuration**. There are two step nodes, one Shared Settings
node, and a live Resolved Export node.

The important part of [shared-state.json](shared-state.json) is:

```json
{
  "steps": [
    { "id": "first", "configRef": "receipt" },
    { "id": "second", "configRef": "receipt" }
  ],
  "configs": {
    "receipt": {
      "config": { "message": "Thank you for your order", "enabled": true }
    }
  }
}
```

Both `configRef` values identify the same record. The complete file also contains
step names and matching `type` values, which the export helper validates.
All three editable nodes have a binding like this in
[shared-bindings.json](shared-bindings.json):

```json
{
  "root.first": {
    "address": "root.configs.receipt.config",
    "type": "DeliveryConfig"
  },
  "root.second": {
    "address": "root.configs.receipt.config",
    "type": "DeliveryConfig"
  }
}
```

1. Double-click **Shared Settings** and change Message. Press Tab to commit.
2. Open **Email Receipt**, then **Email Reminder**. Both forms show the new message.
3. Change Enabled in either form. Here, Enabled is shared too, because the entire
   configuration object is shared.
4. In **Forms**, click **Export example values**. The live Resolved Export node
   displays the same result: two plain `config` objects, no `configs` registry
   and no `configRef` fields.

The host uses the existing
[materializeStepConfigs](../workflow-form/catalog.ts) helper for both the preview
and download. It validates references and clones the values for each exported
step; it does not execute the workflow. A visual connection alone does not make
values shared: the state references and bindings do.

## 2. Share Just One Property

Choose **Reusable Property**. [property-state.json](property-state.json) starts
with different inline messages. Email Receipt is enabled; Email Reminder is not.
[property-bindings.json](property-bindings.json) binds each node to its own config.

1. In **Forms > Reusable configuration**, enable **Message** for `DeliveryConfig`.
   This applies [mapping.json](mapping.json):

   ```json
   {
     "version": 1,
     "fields": [{ "type": "DeliveryConfig", "field": "message" }]
   }
   ```

2. Two message resources appear. Each original field now stores a resource ID.
   Mapping does **not** deduplicate equal text or automatically share resources.
3. Open **Email Reminder** and choose the message belonging to **Email Receipt**.
   Both steps now reference one resource. The old reminder resource may remain
   available; changing a reference does not delete the resource.
4. Open the connected message node and edit Message. Export now contains that
   text in both steps, while their Enabled values remain `true` and `false`.
5. Turn **Message** off in the mapping panel. The latest text returns inline to
   both steps and generated resource nodes disappear. Enabled is unchanged.

The example reuses the same helpers as the full mapping panel:

```ts
const mapped = configureResources({ state, view, schema, bindings }, mapping);
const forms = resourceFormContext(mapped, schema, bindings);
const edited = changeMappedState(mapped, nextState, changedAddress);
const plainData = exportResourceState(edited);
```

See [examples.ts](examples.ts) for the initial setup and
[the lifecycle test](../../tests/configuration-basics.test.ts) for the complete
map, share, edit, export, and inline sequence. IDs are generated by the existing
adapter; never build them yourself. They are references, not the displayed text.
Export removes `sdkResources` and resolves values without modifying the editor state.

## Change It for Your Properties

| File                                             | Change this                                                                    |
| ------------------------------------------------ | ------------------------------------------------------------------------------ |
| [schema.ts](schema.ts)                           | Declare your field names and types; this example has only Message and Enabled. |
| [property-state.json](property-state.json)       | Supply your application values; omit all diagram metadata.                     |
| [property-bindings.json](property-bindings.json) | Map each visual address to the actual state object and schema name.            |
| [mapping.json](mapping.json)                     | Choose exactly which schema field becomes reusable.                            |
| [property-view.json](property-view.json)         | Choose labels, icons and colors independently of data.                         |
| [shared-view.json](shared-view.json)             | See the annotated shared-object graph and visual connections.                  |

`root.first` is a view address; `root.steps.0.config` is a state address;
`DeliveryConfig` is a schema name. They serve different purposes and need not
match. Array bindings must be regenerated if the source array is reordered;
stable record keys avoid that maintenance.

Keep `edgeMode: "auto"` when mixing ordinary and property connections. These
lessons use it by default. Compact layout changes spacing, not data or sharing.
Diagram edits and state edits are held in memory per template; reload starts over.
Download is explicit, not browser-draft storage or a production save.

Once these two examples are familiar, use
[Workflow State's declarative configuration](../workflow-state/README.md#declarative-configuration)
for collections, dependency fields, groups, and file packages. The mapping and
export helpers here are client examples, not automatic SDK backend behavior.
